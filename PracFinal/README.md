# Итоговая практика — сайт ЧистоДома

Итоговая версия сайта клининговой компании: простой адаптивный интерфейс, регистрация, вход, личный кабинет и заявки. Администратор видит все заявки и меняет статусы. Код содержит пояснения для защиты практики.

## Запуск

Нужны Docker и Docker Compose. Откройте терминал в папке PracFinal.

```bash
cp .env.docker.example .env.docker
```

В `.env.docker` задайте разные случайные пароли для PostgreSQL, роли приложения и администратора. Укажите логин администратора. Для `DATA_ENCRYPTION_KEY` создайте ключ Fernet:

```bash
docker run --rm python:3.14-alpine python -c 'import base64,os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())'
```

Сохраните ключ: без него нельзя расшифровать персональные данные. Не публикуйте `.env.docker`.

```bash
docker compose --env-file .env.docker up -d --build
docker compose --env-file .env.docker ps
```

Сайт: https://127.0.0.1:8443/. Сертификат локальный, самоподписанный. Порт 8000 перенаправляет на HTTPS. Порт 5433 предназначен для PostgreSQL, а не для браузера.

Если используется Docker Desktop в Linux, указывайте `docker --context desktop-linux` вместо `docker`. Команда с sudo может обратиться к другому Docker Engine.

Другие проекты на портах 8000, 8443 и 5433 нужно предварительно остановить. У этой папки собственный Compose-проект и том базы; данные прежней Prac3 автоматически не переносятся.

## Защита

- PBKDF2-HMAC-SHA256, случайная соль на 32 байта и 260 000 итераций для паролей.
- Шифрование ФИО, адресов и телефонов Fernet; логины, даты и статусы остаются открытыми.
- Сессионные токены: в базе хранится хеш, в браузере — HttpOnly-cookie с SameSite=Lax и Secure при HTTPS.
- Серверная проверка полей и прав: обычный пользователь видит свои заявки, изменение статуса доступно администратору.
- Параметрические SQL-запросы, безопасный вывод через textContent, проверка Origin для POST и защитные HTTP-заголовки.
- Уведомление о cookie при первом посещении и в новом приватном сеансе; отказ хранилища не мешает показу.
- Непривилегированный пользователь контейнера, read-only файловая система, ограничения ресурсов и локальные порты.

В server.py находятся подробные комментарии к защите. В app.js — работа форм, уведомления и безопасный вывод данных. В index.html — проверки полей браузером. В compose.yaml и db-init/01-roles.sh — настройки контейнеров и прав БД.

Это учебный проект: ограничения попыток входа, автоматические резервные копии и двухфакторная аутентификация не реализованы. Проверка официальными HTML/CSS-валидаторами отдельно не подтверждена. Вспомогательные http_methods_app.py и method_scanner.py рассчитаны на HTTP; для HTTPS их нужно адаптировать. setup_db.py нужен для отдельного локального запуска без Docker.

## Остановка

```bash
docker compose --env-file .env.docker down
```

Данные остаются в томе. Не добавляйте `-v`, если хотите сохранить базу.
