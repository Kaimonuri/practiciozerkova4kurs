# Практическая работа: CORS

Готовый локальный проект по заданию «Задание на CORS (1).docx» и презентации «15-CORS (1).pptx». Windows 11, Python 3.10 или новее, Edge / Chrome / Firefox. Сторонние пакеты, Node.js и отдельный сервер БД не нужны. Используется настоящая SQLite, файл создаётся автоматически.

## Быстрый запуск

1. Распакуйте **весь** архив в обычную папку, например `C:\Study\cors-practice`. Не запускайте файлы внутри ZIP.
2. Установите Python с https://www.python.org/downloads/windows/ и проверьте в терминале `py -3 --version` (версия не ниже 3.10).
3. Откройте `start-before.cmd`. Не закрывайте окно сервера.
4. Откройте **http://localhost:8081**, **http://localhost:8082**, **http://localhost:8083** в браузере. Используйте именно `localhost`, а не `127.0.0.1` и не открытие HTML с диска.
5. Проведите проверки этапа «до» из таблицы ниже. Откройте F12 → Network и Console; включите Preserve log при необходимости.
6. В окне сервера нажмите Ctrl+C и дождитесь остановки. Затем откройте `start-after.cmd`.
7. Обновите все три страницы (Ctrl+F5) и повторите проверки. На приложениях 1 и 3 появится «CORS включён». На приложении 2 он остаётся выключенным.

Запуск из терминала в папке проекта:

```powershell
py -3 server.py --cors off
# После Ctrl+C:
py -3 server.py --cors on
```

Если команда `py` отсутствует, но `python --version` показывает установленный Python 3.10+, используйте `python` вместо `py -3`. Если Windows предлагает Microsoft Store, установите Python и откройте новый терминал.

## Что проверять

| Действие | До CORS | После CORS |
|---|---|---|
| Приложение 1: своя таблица GET | Браузер блокирует чтение; сервер отвечает 200 без ACAO | HTTP 200, три записи primer1 |
| Приложение 2: своя таблица GET | То же | HTTP 200, три записи primer2 |
| Приложения 1 и 2: preflight | OPTIONS 204 без разрешений; основной GET не отправляется | OPTIONS 204 с разрешениями, затем GET 200 |
| Приложения 1 и 2: чужая таблица | Ответ 200 недоступен JavaScript | Сервер 403 без ACAO; JavaScript не читает ответ |
| Приложение 2: запрос к приложению 1 | Ответ 200 недоступен JavaScript | HTTP 200, справочное сообщение |
| Приложение 3: обе локальные проверки | HTTP 200 с данными | HTTP 200 с данными |
| no-cors в приложениях 1 и 2 | opaque, status 0 | opaque, status 0 |

ACAO — сокращение заголовка `Access-Control-Allow-Origin`. Ошибки отображаются прямо на странице. Сам JavaScript не может надёжно отличить блокировку CORS от сетевого сбоя: точную причину показывает Console / Network.

В Network откройте запрос `primer1` и сравните Request Headers → `Origin: http://localhost:8081` и Response Headers → `Access-Control-Allow-Origin: http://localhost:8081`. Для `primer2` разрешён только порт 8082. У OPTIONS должны быть `Access-Control-Request-Method: GET` и `Access-Control-Request-Headers: x-lab-demo`; в ответе разрешены только `GET` и `X-Lab-Demo`. Max-Age равен 0 для удобного повторения опыта.

Для защиты сохраните скриншоты: блокировка до CORS, обе таблицы после CORS, пара OPTIONS/GET, отказ чужой таблице, успешный запрос к приложению 1.

## Структура

```text
server.py          три HTTP-приложения и явная CORS-политика
schema.sql         создание primer1 / primer2 и учебные данные
web/index.html     общая страница трёх приложений
web/app.js         реальные fetch-запросы из браузера
web/style.css      оформление
data/practice.sqlite3  автоматически созданная БД
tests/test_http.py проверка HTTP, данных и ограничений
start-before.cmd   запуск без CORS
start-after.cmd    запуск с CORS в приложениях 1 и 3
test.cmd           автоматические HTTP-проверки
REPORT.md          объяснение работы и ответы для защиты
VERIFICATION.md    протокол выполненной проверки
```

Три отдельных HTTP-сервера работают в потоках одного процесса, чтобы их можно было запустить и остановить одной командой. Разные порты дают разные origin. Общий код не объединяет их сетевые адреса. Только обработчик приложения 3 читает таблицы; клиенты не подключаются к SQLite напрямую. Схема данных в задании не указана, поэтому выбраны учебные поля `id`, `name`, `description`.

## Автоматическая проверка

Остановите приложения, затем запустите `test.cmd` или `py -3 -m unittest discover -s tests -v`. Тест поднимает оба режима на 8081–8083, использует временную БД, проверяет ответы и завершает серверы. HTTP-тест не имитирует защиту браузера, поэтому также выполните проверки интерфейса выше.

## Решение проблем

- `Cannot start` / ошибка 10048: один из портов занят. Остановите предыдущий экземпляр через Ctrl+C. Не меняйте порты по отдельности: они входят в CORS-политику.
- `Failed to fetch` после включения: проверьте адрес `http://localhost`, окно сервера, перезагрузите страницу, посмотрите Console. Не устанавливайте расширения, отключающие CORS.
- Данные не сбрасываются при перезапуске: это ожидаемо. Начальные строки добавляются через `INSERT OR IGNORE`. Для нового учебного набора остановите сервер и удалите только `data/practice.sqlite3`, затем запустите снова.
- Для просмотра SQLite можно пользоваться любым редактором SQLite, но он не нужен для запуска.

Сервер слушает только loopback `127.0.0.1`. Проект предназначен для локальной практики, содержит только учебные данные. CORS здесь управляет чтением ответов браузером; реальная защита конфиденциальных данных требует отдельной аутентификации и авторизации.
