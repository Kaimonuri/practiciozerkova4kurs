# Протокол проверки

Дата: 24 сентября 2026 года. Среда выполнения: Windows, Python 3.12.14. Браузер: встроенный браузер Codex. Проверка в отдельных установках Edge, Chrome и Firefox не проводилась. Установка Python и запуск двойным щелчком на чистой Windows 11 не проверялись; `.cmd` запускают те же команды Python, которыми проверен сервер.

## HTTP и SQLite

Команда: `python -m unittest discover -s tests -v`.

Результат: `Ran 1 test in 2.636s — OK`. Один интеграционный тест содержит проверки обоих режимов и следующих сценариев:

- Доступность страниц всех трёх приложений.
- Выдача по три строки из каждой таблицы и правильные имена таблиц.
- Точный ACAO только для разрешённой пары «маршрут / origin».
- Отсутствие Allow-Credentials и CORS-заголовков у приложения 2.
- Отказ источникам `null`, внешнему сайту, похожему имени хоста, чужому порту и адресу 127.0.0.1 вместо localhost.
- Разрешённый OPTIONS для GET / X-Lab-Demo, запрещённые DELETE и Authorization.
- Прямой запрос без Origin, неизвестный маршрут, неподдерживаемый POST и невозможность скачать server.py через HTTP.

## Проверка реальным браузером

| Проверка | Полученный результат |
|---|---|
| До: приложение 1 → primer1 | На странице Failed to fetch, в журнале сервера GET 200 |
| До: приложение 2 → primer2 | На странице Failed to fetch, в журнале сервера GET 200 |
| До: оба клиента, X-Lab-Demo | OPTIONS 204, основного GET от этой проверки нет, чтение не удалось |
| До: приложение 2 → /api/info приложения 1 | Failed to fetch при серверном 200 |
| До: приложение 3 → обе собственные таблицы | HTTP 200, по три записи |
| До: no-cors из приложения 2 | OPAQUE, status 0 |
| После: приложение 1 → primer1 | HTTP 200, HTML / CSS / JavaScript |
| После: приложение 2 → primer2 | HTTP 200, CORS / CSP / SQLite |
| После: оба клиента, X-Lab-Demo | OPTIONS 204, затем GET 200 и данные |
| После: каждый клиент → чужая таблица | В журнале 403, в интерфейсе Failed to fetch |
| После: приложение 2 → /api/info приложения 1 | HTTP 200, справочное сообщение |
| После: приложение 3 → обе собственные таблицы | HTTP 200, по три записи |
| После: no-cors из приложения 1 | OPAQUE, status 0 |
